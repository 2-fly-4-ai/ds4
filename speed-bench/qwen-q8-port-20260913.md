# Focused Qwen Q8 verifier port — 2026-09-13

Parent: production main `70d948a`. Branch: `port/qwen-q8-exact-20260913`. This is a focused reconstruction, not a merge of the wide experimental branch. No quant, model-file, power, or fan-setting changes.

## Production scope

- Add a Qwen-only Metal entry point for scalar-matched Q8 verifier projections, using two input rows per group for widths 2–3 and four for widths 4–16. No environment flag is required.
- Keep scalar K traversal and reduction order. Qwen's SIMD-group cutoff now matches scalar decode at output dimension >4096.
- Preserve the generic exact-Q8 entry point's existing dispatch for GLM and DeepSeek. The private implementation receives an explicit boolean; no global model-detection flag changes other callers.
- Allow Q4_K gate/up plus MXFP4 down Qwen trunks to use the wide verifier. Exact verifier rows cannot use half-rounded expert prefill GEMMs. The Q4_0 half-intermediate predicate is unchanged.
- All new scheduling selection is Apple-only. CUDA/ROCm keep their existing calls and scheduling decisions. Distributed Qwen sessions remain unsupported, as before.
- No paired-expert, grouped-expert, GPU-profiling, routing-dump, or other speculative experimental changes were included.

## SSD regression

The resident Q4_K/MXFP4 quant is rejected by existing main in SSD mode (`requires IQ2_XXS gate/up and MXFP4 down`). This port intentionally does not add support for that combination.

The supported installed IQ2_XXS/MXFP4 Qwen model was tested instead, with a 4 GiB expert cache, context 2048, MTP on, temperature 0, 36 prompt tokens and 32 generated tokens. Main and port emitted identical bytes; both reported 16 verifier cycles and 15 drafts accepted. `QWEN_Q8_SSD_OUTPUT_PARITY_PASS`.

The OS file cache was warm and only one run per arm was performed; SSD prefill differed heavily by cache state. These runs prove a bounded regression smoke, not an SSD throughput gain. Prompt lookup remains disabled for SSD Qwen sessions.

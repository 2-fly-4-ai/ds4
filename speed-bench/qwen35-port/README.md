# Small-Qwen runtime and hot-cache validation

2026-09-14. Focused port based on main `7f69f18`; no wholesale upstream merge
and no quantization changes. Final local validation passed before integration.

## Implementation

- Qwen3.6-35B-A3B Q8: 40 trunk layers, 32-value-head GDN, 16/2 full-attention
  geometry, 256-expert/top-8 FFN and gated shared expert. Reuses existing Qwen
  Next GPU MoE operations. The 27B GDN kernel is unchanged.
- Native block 40 is the MTP head, not an extra trunk layer. BF16 projections
  use the existing GPU dispatch. No sidecar is required for this installed file.
- 27B Q8/Q4 math remains in place; allocation, hidden copies and MTP KV reset
  dimensions now follow the model instead of assuming 27B.
- Exact process-local prompt snapshots retain recurrent/convolution state,
  live full-attention KV, MTP KV/history, hidden and logits. They restore
  ownership after another logical session uses the shared GPU pool.
  Changed prompts invalidate stale marks. This saves repeated prefill, not
  ordinary decoding.
- Generic DS4 disk payloads are explicitly refused for small Qwen: live rewind
  is supported, durable small-Qwen KV is not.
- Pool teardown releases tensors and the MTP sidecar before Metal cleanup.
  Decode/verifier bounds protect the existing 4096-token small-Qwen cache.
- New 35B support is resident Metal only. CPU, SSD and distributed modes are
  refused for this shape; existing model backends are unchanged.

## Evidence

`RESULTS.md` is generated by `tests/summarize_qwen_runtime.py` from raw API JSON
in `speed-bench/api-health/`. The five archived tasks are coding, story,
reasoning, JSON and code editing, at short and approximately 2K prompts. Actual
token counts are reported. Each runs cold and repeated, MTP off/on, temperature
zero, capped at 256 output tokens. Cap-ended answers are not complete tasks.

Decode rates exclude TTFT and are client-observed. These are single-run
measurements under sustained load, not confidence intervals or proof that the
port accelerated every pre-existing decode kernel. MTP speed claims require
identical outputs. Cache gains are separate. 35B short story-writing can be
slower with MTP.

Checks: metadata/tokenizer contracts; 32 GDN synthetic cases versus a double
oracle with exact batch/scalar state and prefix snapshots; model-shaped Q8
MoE/routing versus a double oracle; 96-token serial/MTP parity; exact hot-logit
restore after interleaving; stale-mark rejection; disk-payload refusal;
engine close/reopen; server unit tests. DeepSeek 0731, Vision-Exp, V4.1 safe SSD,
GLM and Qwen Next replay archived requests. Raw logs record individual outcomes.

No large CPU inference or V4.1 encoder-residency experiment is included. Model
processes run sequentially. API probes use the existing memory/swap guard.
CUDA/distributed runtime validation is not claimed on this Mac.

Final outcome: 120 small-Qwen API requests, 30/30 MTP-off/on exact workload
pairs, 60/60 cold/repeat exact pairs with positive cache reuse, and 25/25 exact
archived existing-model regression replies. All synthetic and reopen checks
passed. No crash or memory-guard failure occurred.

## Independent 35B reference check

The old engine's default FP16 attention-cache shadow is not a precision-matched
reference. It differed by up to 0.5093 in full logits despite matching all 32
next-token choices. Disabling its rows4 GDN variant alone made no difference.
Disabling the FP16 shadow as well reduced maximum absolute error to
0.00000953674 over 7,946,240 logits (32 rows, vocabulary 248320), with 32/32
matching next-token choices. See `fixed-logits-f32-comparison.log`.

The public-API probe feeds identical token IDs to both engines, since their
chat tokenizers/templates differ. Reference controls:

```sh
DS4_QWEN_DECODE_SHADOW=0 DS4_QWEN_GDN_ROWS4=0 DS4_QWEN_PREFILL_BATCH=0 DS4_QWEN_NEXTN_DRAFT=0
```

Only the reference uses the first two controls; candidate prefill is scalar
for this math comparison. The production API benchmarks retain normal batched
prefill. No tolerance was relaxed and the candidate implementation was not
changed to imitate FP16 rounding. The older API comparison is a smoke test,
not a matched speed claim, because its prompt token counts differ.

## Reproduce

Build:
```sh
make -j4 ds4 ds4-server ds4_test tests/test_qwen_small_runtime tests/test_qwen35_gdn_port tests/test_qwen35_moe_port
sh tests/qwen_runtime_final_checks.sh
```

Run the final checks only after other model processes exit.
The API helper accepts `HEALTH_CONTEXTS=short,2048`, `HEALTH_REPEAT=2`,
`HEALTH_CHAT=1`, `HEALTH_MTP_OFF=1` and `HEALTH_MODEL_FILE`.

Serve installed 35B with its native greedy MTP:
```sh
cd /Users/brianfarley/Desktop/ds4
./ds4-server --metal --ctx 4096 --host 127.0.0.1 --port 8000 -m gguf/qwen-small-quality/35b-mtp/Qwen3.6-35B-A3B-Q8_0.gguf
```

For MTP-off control, prepend `DS4_QWEN_NEXTN_DRAFT=0`. For 27B keep
`DS4_QWEN_MTP_HEAD` pointed at its installed sidecar. Do not carry that 27B
sidecar environment into a 35B launch.
